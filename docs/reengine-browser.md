# RE Engine 扩展浏览器与轻量预览

资产库插件 0.25.3 增加此功能，面向提供 `_remote_asset_browser.API_VERSION == 1` 和
`gpu.texture.from_bytes()` 的自定义 Blender 5.2。浏览器 provider 的稳定 ID
是 `reengine`。官方 Blender 的原有资产库工作流继续保留。

0.25.4 改为只读 PAK 预览，并优化首屏、纹理解码和重复请求缓存。

## 预览与完整导入

扩展浏览器使用现有资产目录 TSV、GameInfo 和提取配置定位资源；文件树在
本机 loopback HTTP 服务上提供，游戏 PAK 与格式解释仍由插件处理。

- 模型预览优先使用第三级 `LOD2`；不存在或没有有效几何时，依次回退到
  `LOD1`、`LOD0`。不会选择 `LOD3` 或更低精度的级别。
- 预览只使用基础颜色贴图、基础颜色参数和简单固定光照；不模拟完整 MDF
  节点材质，不加载法线、粗糙度、金属度或 AO 作为预览着色输入。
  以不透明 RGB 显示，不将基础颜色贴图中可能存放金属度/遮罩的 alpha
  通道误当成透明度。
- 预览几何通过 GPU 顶点/索引批次绘制，纹理解码成 RGBA 字节后通过
  `gpu.texture.from_bytes()` 上传；不为预览创建场景对象或 Image 数据块。
- 预览不会提取游戏资源到磁盘，也不会调用完整依赖提取或继承“强制提取文件”。
  它复用现有 PakCache 索引，从 PAK 按补丁优先级读取所需资源到内存；没有对应
  PAK 条目时可只读访问已配置的 chunk 文件。没有可用索引或资源时会明确报错，
  不在预览中自动重建索引或展开游戏文件。纹理转换使用完即删除的临时 DDS/TGA。
- 几何解析完成即可显示，贴图随后更新。基础颜色 TEX 优先选择约 512 像素的
  mip；没有足够小的 mip 时使用最小可用级别。同一纹理由多个材质段共享。
- 预览数据与解码贴图分别使用有上限的内存缓存，重复选择可复用；点击刷新
  或禁用插件会清理缓存。文件修改、PAK 或 GameInfo 变化会使对应缓存失效。
- 完整导入仍由原 RE Mesh Editor 导入器创建模型、骨骼、权重和材质。
  完整导入继续使用原有资源提取设置和 Mesh Editor 导入选项，预览的 LOD 与
  贴图预算不会覆盖全量导入质量。扩展面板不增加“提取文件”开关。

当前轻量预览针对普通 RE Mesh。MPLY meshlet 需要额外的分块位置变换，
本次明确报告暂不支持其预览；仍可使用原插件执行完整导入。

## 另一台电脑的准备

1. 使用与本接口匹配的自定义 `blender-ue-dev.exe`；保留其配套 DLL 和
   `5.2` 脚本目录。仅版本号为 5.2 不代表支持此扩展 API。
2. 更新本分叉的 `feat/onimusha-wots` 分支，安装更新后的资产库插件。
   安装目录继续使用原来的 `RE-Asset-Library-main`，避免同时启用多个副本。
3. 启用配套的 RE Mesh Editor；OWOTS 需要本分叉的对应格式适配版本。
4. 在资产库设置中确认资产库目录、游戏 EXE、提取目录与 RE Mesh Editor
   的 chunk 路径都属于当前电脑。Git 不包含游戏资源、PAK 缓存或个人路径配置。
5. 在文件浏览器的扩展模式中选择 `RE Engine`，导航到模型文件；保留一个
   3D 视口用于预览。基础目录浏览不需要先导入资产占位对象。

## 实测清单

静态检查与单元测试不能替代下面的真实资源和界面验收。请在持有游戏资源的
电脑上记录使用的插件提交和自定义 Blender 程序版本。

预览面板显示所选 LOD、顶点/三角形数量和解码错误。缺失基础颜色纹理时
几何仍可显示，但应检查面板中的原因，不要将纯色回退当成贴图加载成功。

| 检查 | 预期结果 |
| --- | --- |
| 注册与导航 | 出现 `RE Engine`；根目录、子目录、上级和 Home 正常 |
| 普通选择 | 选择条目不会立即执行完整导入 |
| 模型预览 | 双击模型后在 3D 视口出现预览，场景对象数量不增加 |
| LOD2 | 对包含三级以上 LOD 的模型，预览使用 LOD2 |
| LOD 回退 | 只有两级时使用 LOD1，只有一级时使用 LOD0 |
| 基础颜色 | 多材质的颜色贴图与材质槽对应；无基础颜色贴图时仍可显示纯色 |
| 快速切换 | 连续选择不同模型，旧请求完成后不会覆盖最新预览 |
| 清理 | 关闭预览或禁用插件后不再绘制，GPU 引用与后台服务被清理 |
| 完整导入 | 点击导入后走原选项与 Mesh 导入流程，得到真实对象、骨骼与材质 |
| 取消导入 | 取消选项窗口不应显示为已完成导入 |
| provider 隔离 | 与 FModel / NG4Tool 切换后，路径、动作和预览不串台 |
| 错误反馈 | 缺失模型、贴图或提取配置时有可读错误；不影响其他 provider |

对于 OWOTS 的 `ch001_00_00.mesh`，已有完整导入记录可作为对照：
LOD0 为 48,909 个源顶点，LOD2 为 16,643 个源顶点。GPU 数据可能因
材质划分或共享顶点处理而使用不同的缓冲计数，判断 LOD 应同时核对源级别。
原有完整导入证据见 [onimusha-quality-validation.md](onimusha-quality-validation.md)。

请分别记录预览和完整导入的结果；预览颜色正确不代表完整 MDF 材质已通过，
operator 返回成功也不代表骨骼、权重和模型外观全部正确。
